# HTTP lab

Задание: ускорить HTTP-сервис, сохранив результаты поиска.
Сервер обрабатывает запросы последовательно, на каждый запрос заново читает
JSONL-каталог и сортирует все совпадения. Искусственных задержек нет.

Python 3.10+, внешних зависимостей нет.

## Своя копия

1. Нажмите **Use this template → Create a new repository**.
2. Назовите репозиторий `http-lab-<ваш GitHub-логин>`, выберите **Private**.
3. В **Settings → Collaborators** добавьте преподавателя `codeforcesrankzero`.
4. Клонируйте свою репу. До первых изменений создайте метку исходника:

```bash
git tag baseline
```

## Запуск

Из корня репозитория:

```bash
python3 make_data.py --rows 50000 --seed 42
python3 server.py
```

В другом терминале:

```bash
curl -sS 'http://127.0.0.1:8080/search?q=book'
python3 client.py --requests 200 --concurrency 8
```

Остановка сервера — `Ctrl+C`.

## Поиск

`GET /search?q=book` ищет подстроку в `title` без учёта регистра.
Параметр `q` обязателен: одна строка длиной 1–64 символа.
Ответ: `{"total": 123, "items": [...]}`. В `items` не больше 10 записей
с полями `id`, `title`, `score`: сначала больший `score`, при равенстве — меньший `id`.
Без совпадений: `{"total": 0, "items": []}`.

Каталог во время работы не меняется. Можно менять реализацию сервера и клиента.
Размер каталога и результат поиска должны сохраниться.

## Замеры

Сравните исходную версию (тег `baseline`) и свою на одной машине и одном каталоге:

```bash
python3 client.py --requests 500 --concurrency 1
python3 client.py --requests 500 --concurrency 8
python3 -m unittest discover -s tests -v
```

Клиент выводит JSON: `successful_rps` — успешные запросы в секунду,
`successful_latency_ms` — задержки успешных запросов, `failed` и `errors` — ошибки.
По умолчанию он делает 5 запросов прогрева, не входящих в замер.
Каждый работник ждёт ответ перед следующим запросом; соединение каждый раз новое.
Повторите замеры трижды. Итоговую скорость измеряйте без профилировщика.

## perf

Нужны Linux, установленный `perf` и CPython 3.12+ с поддержкой `-X perf`.
Остановите обычный сервер и запустите его под `perf`:

```bash
perf record -F 99 -g -o perf.data -- python3 -X perf server.py
```

В другом терминале запустите клиент. Когда нагрузка закончится, остановите
сервер через `Ctrl+C` и сохраните отчёт:

```bash
perf report -i perf.data --stdio > perf.txt
```

Найдите, где расходуется CPU. Имена Python-функций и полнота стеков зависят
от сборки интерпретатора.

## Как сдать

Запушьте код в свою репу. Добавьте `REPORT.md`:

- Параметры запуска и версию Python.
- Таблицу до/после: RPS, p50/p95/p99, ошибки.
- Короткий вывод: что тормозило, что изменили, какой получили результат.
- Результат запуска тестов.

Приложите `perf.data` и `perf.txt`. Передайте преподавателю ссылку на репозиторий
и хеш итогового коммита (`git rev-parse HEAD`).
